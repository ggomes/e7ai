# Plain-English Logic Prompts: Hovering Drone

## The Natural Language Controller

In this exercise, you will use GitHub Copilot as a programming assistant. You
will describe an engineering control policy in plain English comments and ask
Copilot to complete the Python control flow.

The drone model in `drone_system.py` is provided as a black-box module. Do not
modify it. Your job is to write the controller around the model; the drone
dynamics are not the part of the system that you are delegating to Copilot.

## Learning goals

By the end of this exercise, you should be able to:

- express an engineering rule precisely enough for another programmer to
  implement;
- recognize the parts of a simulation loop: observe, decide, actuate, and
  advance;
- understand how position and velocity feedback create a second-order control
  problem;
- use Copilot to generate a small piece of code without surrendering design
  decisions to it;
- read, run, test, and explain code generated by Copilot.

## Setup

Open this folder in VS Code. The repository includes Copilot instructions and
an activity tutor prompt in `.github/`. If Copilot Chat is not already open,
open it from the VS Code activity bar and use the prompt in the notebook or
invoke `.github/prompts/session0-1-tutor.prompt.md`.

Start by sending Copilot Chat:

> Please run the simulator with the default controller and show me the output.
> Also, explain to me in plain English what the controller is doing.

The starter runs, but its initial policy is deliberately incomplete; use the
output and explanation to identify what still needs to be specified.

Read the docstrings in `drone_system.py`, but do not edit that file. The
provided constants and function are the external system interface:

- `V_MAX` is the largest allowed motor voltage.
- `advance(current_position, current_velocity, voltage)` advances the drone
  by one simulated time step and returns its new position and velocity.

The model is one-dimensional: the drone can move only vertically. Its
acceleration follows Newton's second law. The forces are upward propeller
thrust, downward gravity, and viscous damping opposing velocity. The thrust
is proportional to voltage. The propellers cannot push downward, so a voltage
of zero produces free fall.

## Engineering specification

The drone starts at rest on the floor at height 0 m and the desired height is
10 m. Each loop iteration represents 0.1 seconds. Your controller must:

- bring the drone within 0.15 m of 10 m;
- settle by the end of step 70;
- remain within that tolerance through step 100.

The script reports whether the specification was met and produces
`drone_response.png`. The plot includes the target height, the allowed
tolerance band, and the simulated response.

The specification is intentionally not satisfied by simply applying maximum
voltage until the target is reached and then setting voltage to zero. The
drone has inertia and will continue moving after the voltage changes. You must
use velocity feedback to brake and use enough voltage near the target to
balance gravity and damping. Do not change `drone_system.py` to make the test
pass.

## Activity

1. In `student_controller.py`, replace the example comments with your own
   plain-English control rules. Include rules for:

   - what to do when the drone is substantially above the target;
   - what to do when it is substantially below the target;
   - how upward velocity should affect the voltage while approaching the
     target;
   - how to hover near the target despite gravity;
   - how to clamp the command to the range 0 to `V_MAX`.

2. Put the cursor in the control-flow block and press **Tab** to accept a
   Copilot suggestion. You may revise or reject the suggestion. Ask Copilot to
   help expand the starter into an `if`/`elif`/`else` structure, but decide
   whether the generated conditions and actions match your rules.

3. Run the controller. Use the printed position and velocity values,
   pass/fail report, and `drone_response.png` to determine whether the height
   meets the specification.

4. Change the initial height, initial velocity, and target height and run the
   program again. Explain whether your policy still makes sense when starting
   above the target or moving downward.

5. Add a short explanation at the bottom of `student_controller.py` describing
   one Copilot suggestion you accepted, one change you made, and how you
   verified the result.

## Discussion questions

- Which parts of the program were engineering decisions, and which parts were
  syntax or bookkeeping?
- What assumption did Copilot make that you had to check?
- What test would reveal a controller that never reaches the target?
- Why can a controller appear to settle while still missing the desired
  height?
- Why should the code in `drone_system.py` remain human-written and
  maintained?

## Important boundary

Copilot may help write the controller, but it is not the authority on the
behavior of the drone. You are responsible for checking the generated code,
testing edge cases, and explaining what it does.
