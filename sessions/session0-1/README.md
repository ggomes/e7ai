# Plain-English Logic Prompts

## The Natural Language Controller

In this exercise, you will use GitHub Copilot as a programming assistant. You
will describe an engineering control policy in plain English comments and ask
Copilot to complete the Python control flow.

The tank model in `tank_system.py` is provided as a black-box module. Do not
modify it. Your job is to write the controller around the model; the tank
dynamics and valve logic are not the part of the system that you are
delegating to Copilot.

## Learning goals

By the end of the exercise, you should be able to:

- express an engineering rule precisely enough for another programmer to
  implement;
- recognize the parts of a simulation loop: observe, decide, actuate, and
  advance;
- use Copilot to generate a small piece of code without surrendering design
  decisions to it;
- read, run, test, and explain code generated by Copilot.

## Setup

Open this folder in VS Code. Open `student_controller.py` and make sure
Copilot is enabled. The starter runs, but its initial policy is deliberately
incomplete; use it to identify what still needs to be specified.

Read the docstrings in `tank_system.py`, but do not edit that file. The
provided functions are the external system interface:

- `set_valve_position(current_level, target_level)` returns a valve command
  between -100 and 100. Negative values drain the tank; positive values fill
  it. The second argument is the desired operating level supplied to the
  black-box valve controller.
- `advance(current_level, valve_position)` advances the tank by one simulated
  time step.

## Engineering specification

The tank starts at 10% full and the desired tank level is 70%. Each loop
iteration represents one second. Your controller must:

- bring the tank within 1.5 percentage points of 70%;
- settle by the end of step 15;
- remain within that tolerance through step 30.

The script reports whether the specification was met and produces
`tank_response.png`. The plot includes the desired level, the allowed
tolerance band, and the simulated response.

The specification is intentionally not satisfied by simply passing 70.0 to
the provided function on every iteration. The supplied tank has a small leak,
so you must observe the response and decide how your control policy should
compensate. Do not change `tank_system.py` to make the test pass.

## Activity

1. In `student_controller.py`, replace the example comments with your own
   plain-English control rules. Include rules for:

   - what to do when the level is substantially above the target;
   - what to do when the level is substantially below the target;
   - what to do when the level is close to the target;
   - how to compensate for the tank's persistent leak.

2. Put the cursor in the control-flow block and press **Tab** to accept a
   Copilot suggestion. You may revise or reject the suggestion. Ask Copilot to
   help expand the starter into an `if`/`elif`/`else` structure, but decide
   whether the generated conditions and actions match your rules.

3. Run the controller. Use the printed values, pass/fail report, and
   `tank_response.png` to determine whether the level meets the specification.

4. Change the initial level and target level and run the program again. Explain
   whether your policy still makes sense when starting above the target.

5. Add a short explanation at the bottom of `student_controller.py` describing
   one Copilot suggestion you accepted, one change you made, and how you
   verified the result.

## Discussion questions

- Which parts of the program were engineering decisions, and which parts were
  syntax or bookkeeping?
- What assumption did Copilot make that you had to check?
- What test would reveal a controller that never reaches the target?
- Why can a controller appear to settle while still missing the desired level?
- Why should the code in `tank_system.py` remain human-written and maintained?

## Important boundary

Copilot may help write the controller, but it is not the authority on the
behavior of the tank. You are responsible for checking the generated code,
testing edge cases, and explaining what it does.
